# دسترسی همکاران فروشگاه (سطح صفحه)

> وضعیت: **پیاده‌سازی و آزموده**. کد: `app/Models/Membership.php` (`PERMISSIONS`, `GROUPS`, `PRESETS`, `IMPLIES`, `HOME_ROUTES`, `normalize()`, `homeRoute()`)، `app/Http/Middleware/RequirePermission.php` (`perm:a|b`)، `UsersController`، `resources/views/app/partials/permission-picker.blade.php`، `resources/js/pages/users.js`. آزمون: `tests/Feature/TeamPermissionsTest.php`.

## ۱. قواعد

- مالک فروشگاه با شماره موبایل همکار اضافه می‌کند. همکار با کد پیامکی یا اثر انگشت وارد می‌شود و دعوت را در «تنظیمات» می‌پذیرد.
- **پیش‌فرض همه دسترسی‌ها**. تعیین دسترسی در **زمان افزودن** و بعداً با «ویرایش دسترسی» فقط با قابلیت `team.permissions_edit` ممکن است (پلن پایه و حرفه‌ای؛ بدون شرط روی نام پلن).
- در پلن رایگان همه همکاران دسترسی کامل دارند. با کاهش پلن، محدودیت‌های ذخیره‌شده حفظ می‌شوند ولی اعمال نمی‌شوند.
- مدیریت کاربران فقط برای مالک است. مالک همیشه همه دسترسی‌ها را دارد.
- دست‌کم یک دسترسی لازم است (`422 PERMISSIONS_EMPTY`).
- مظنه و ماشین‌حساب همچنان از نظر **پلن و سهمیه** همیشه در دسترس‌اند. محدود کردن آن‌ها برای یک همکار تصمیم صریح مالک فروشگاه است (درخواست مالک محصول، ۱۴۰۵/۰۷).

## ۲. فهرست دسترسی‌ها

| گروه | کلید | برچسب | صفحه/API |
|---|---|---|---|
| قیمت و محاسبه | `mazneh.view` | مظنه | `/mazneh` |
| | `calculator.use` | ماشین‌حساب طلایی | `/calculator` |
| فاکتور | `invoice.issue` | فاکتور جدید (ساخت و صدور) | `/invoices/new`، اقلام، مرور، صدور، اشتراک و پیامک |
| | `invoices.view` | فاکتورها (فهرست، مشاهده و چاپ همه) | `/invoices`، `GET /api/invoices`، جزئیات/چاپ همه فاکتورها |
| | `invoice.void` | ابطال و فاکتور جایگزین | API ابطال/جایگزین (نیازمند `invoices.view`) |
| مشتریان | `customers.view` | فهرست مشتریان | `/customers`، جزئیات مشتری، جستجو |
| | `customers.manage` | افزودن/ویرایش، اقساط، ثبت پرداخت | API مشتری و اقساط (نیازمند `customers.view`) |
| مدیریت | `reports.view` | داشبورد و گزارش فروش | `/dashboard` |
| | `settings.manage` | تنظیمات فروشگاه و ظاهر فاکتور | |
| | `billing.manage` | خرید پلن و اعتبار پیامک | |

- **وابستگی‌ها** (`IMPLIES`) در سرور و در UI اعمال می‌شوند: تیک «ابطال» تیک «فاکتورها» را هم می‌زند، و برداشتن «فاکتورها» تیک «ابطال» را برمی‌دارد.
- **فروشنده بدون «فاکتورها»**: فقط فاکتورهایی را می‌بیند و چاپ می‌کند که خودش ساخته یا صادر کرده است (`created_by`/`issued_by`). بقیه فاکتورها `403` می‌دهند.
- جستجوی مشتری برای خریدار فاکتور با `customers.view` **یا** `invoice.issue` مجاز است (`perm:customers.view|invoice.issue`).

## ۳. نقش‌های آماده (یک لمس، سپس قابل ویرایش)

| نقش | دسترسی |
|---|---|
| دسترسی کامل | همه (جز مدیریت کاربران) |
| فروشنده | فاکتور جدید، مظنه، ماشین‌حساب، فهرست مشتریان |
| صندوق‌دار | فروشنده + همه فاکتورها + مدیریت مشتری و ثبت پرداخت |
| فقط قیمت | مظنه، ماشین‌حساب |
| حسابدار | فاکتورها، مشتریان، داشبورد (بدون صدور) |

## ۴. UI و UX

- **افزودن همکار** (`/settings/users`): موبایل ← «همکار به چه بخش‌هایی دسترسی داشته باشد؟» ← تراشه‌های نقش آماده با یک خط توضیح ← چک‌لیست چهارگروهی با کارت‌های بزرگ (≥۴۸px) ← شمارنده «N دسترسی انتخاب شده» ← «افزودن». تراشه نقشی که با تیک‌های فعلی می‌خواند، روشن می‌ماند.
- **کارت هر همکار**: نشان «دسترسی کامل» یا نشان‌های کوتاه هر دسترسی + «ویرایش دسترسی» (باز شونده با همان انتخابگر) + «حذف».
- **منو**: تب‌های موبایل و منوی دسکتاپ فقط صفحه‌های مجاز را نشان می‌دهند. «بیشتر/تنظیمات» همیشه هست.
- **بعد از ورود**: `GET /home` همکار را به اولین صفحه مجاز می‌برد (فاکتور جدید ← فاکتورها ← مظنه ← ماشین‌حساب ← داشبورد ← مشتریان ← تنظیمات).
