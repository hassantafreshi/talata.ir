# گزینه‌های طراحی با Claude برای Zarlio.ir

تاریخ بررسی منابع عمومی: 2026-10-05. وضعیت: پیشنهاد برای انتخاب مالک؛ هیچ ابزار یا Skill نصب نشده است.

## تفاوتی که در انتخاب مهم است

**Skill طراحی** به Claude روش تصمیم‌گیری، نقد یا بهبود طراحی می‌دهد. **کتابخانه UI** کنترل‌هایی مانند فرم، Select و Dialog فراهم می‌کند. **قالب** ترکیب‌بندی آماده صفحه است. این سه یک چیز نیستند؛ ظاهر متفاوت و UX مناسب از شناخت کار فروشنده و طراحی اختصاصی حاصل می‌شود.

تناسب‌ها در این سند قضاوت پروژه‌ای هستند، نه نتیجه تست با کاربران Zarlio. نمونه‌ها متعلق به سازندگان‌اند و کیفیت نمونه، تضمین خروجی Claude یا دسترس‌پذیری نهایی نیست.

## ۲. کتابخانه‌های قابل بررسی برای Vue/Laravel

Vue + Inertia پیشنهاد فنی فعلی است. اگر انتخاب نهایی stack تغییر کند، این جدول باید دوباره ارزیابی شود.

| گزینه | نکته منبع اصلی | تناسب پیشنهادی | هزینه/ریسک طراحی |
| --- | --- | --- | --- |
| **PrimeVue در حالت Unstyled** | رفتار کامپوننت‌ها همراه امکان حذف استایل آماده؛ RTL مستند | پیشنهاد اول برای فرم، فهرست و عملیات فروشگاهی با ظاهر اختصاصی | طراحی و آزمون استایل تمام وضعیت‌ها بر عهده تیم است |
| **Reka UI** | primitiveهای بدون استایل و راهنمای RTL با ConfigProvider | آزادی بصری زیاد؛ مناسب سیستم طراحی اختصاصی | مونتاژ/طراحی اجزای پیچیده و نگهداری بیشتر |
| **Nuxt UI** | مبتنی بر Reka و Tailwind؛ سازنده استفاده در Vue/Vite/Inertia را اعلام می‌کند | توسعه سریع‌تر با توکن‌ها و اجزای هماهنگ | باید ظاهر و layout پیش‌فرض را برای محصول بازطراحی کرد؛ راه‌اندازی انتخابی با Inertia باید spike شود |
| **shadcn-vue** | مبنایی برای سیستم طراحی Vue و کامپوننت‌های قابل سفارشی‌سازی | گزینه جایگزین، اگر الگوی رفتاری/اجزا را بپسندید | با استفاده مستقیم از نمونه‌ها خطر ظاهر آشنای همیشگی باقی است |

نمونه‌ها و مستندات:

- PrimeVue: [کامپوننت‌ها و دموها](https://primevue.dev/) · [فرم‌ها](https://primevue.dev/forms/) · [DataTable](https://primevue.dev/datatable/) · [Unstyled](https://primevue.dev/theming/unstyled/) · [RTL](https://primevue.dev/guides/rtl/)
- Reka: [سایت و نمونه‌ها](https://reka-ui.com/) · [RTL](https://reka-ui.com/docs/guides/i18n) · [ریپو](https://github.com/unovue/reka-ui)
- Nuxt UI: [سایت](https://ui.nuxt.com/) · [نمونه قالب‌ها](https://ui.nuxt.com/templates) · [ریپو](https://github.com/nuxt/ui)
- shadcn-vue: [نمونه‌ها](https://www.shadcn-vue.com/) · [ریپو](https://github.com/unovue/shadcn-vue)

RTL مستند با «فارسی کامل» یکسان نیست: ورود ارقام، تاریخ شمسی، چاپ، واحد پول و چینش متن ترکیبی هنوز طراحی و تست اختصاصی می‌خواهند. ادعای دسترس‌پذیری کامپوننت به‌تنهایی نشان‌دهنده دسترس‌پذیری کل برنامه نیست.

نسخه رایگان core و مجوز دقیق همان نسخه باید قبل از نصب بررسی شود. افزونه‌ها، قالب‌ها، designerها یا طرح‌های تجاری ممکن است شرایط جدا داشته باشند. این پیشنهاد خرید هیچ بسته پولی را لازم نمی‌کند.

## ۳. گزینه‌های جذاب ولی خارج از اولویت پنل فروشنده

| گزینه | منبع/نمونه | دلیل خارج‌بودن از انتخاب اصلی |
| --- | --- | --- |
| Magic UI | [سایت](https://magicui.design/) | اجزای متحرک مبتنی بر React؛ برای بخش معرفی احتمالی جذاب‌تر از فرم معامله در Vue است |
| Aceternity UI | [دموها](https://ui.aceternity.com/components) | اجزای React/Next با تمرکز نمایشی؛ برای مسیر محاسبه و ثبت پرداخت انتخاب اول نیست |

ممکن است برای سایت معرفی آینده از این‌ها الهام محدود بگیریم. برای افزودن افکت به پنل مالی، تغییر stack یا انتقال انیمیشن‌های سنگین از آن‌ها پیشنهاد نمی‌شود.

## ۴. سه ترکیب برای تصمیم شما

| مسیر | ترکیب | چه زمانی انتخاب شود؟ |
| --- | --- | --- |
| **A — پیشنهاد اول** | Impeccable + PrimeVue Unstyled + طراحی اختصاصی Zarlio | فرم و فهرست‌های غنی، توسعه عملی و ظاهر مستقل را می‌خواهید |
| **B — آزادی بیشتر** | Impeccable + Reka UI + سیستم طراحی اختصاصی | کنترل بسیار زیاد بر شکل و ترکیب اجزا ارزش هزینه اجرای بیشتر را دارد |
| **C — اجرای سریع‌تر** | یک Skill منتخب + Nuxt UI با theme/layout اختصاصی | اجزای هماهنگ آماده و زمان کمتر اولویت دارد؛ با بازطراحی جدی نمونه پیش‌فرض |

UI UX Pro Max می‌تواند پس از انتخاب به‌عنوان منبع محدود ایده/چک استفاده شود. نصب هم‌زمان چند Skill با دستورهای متعارض توصیه پیش‌فرض نیست. اگر انتخاب شد، نقش و تقدم قواعد باید نوشته شود. Anthropic frontend-design گزینه‌ای برای شروع جهت بصری است، با قواعد UX این پروژه در اولویت.

این ترکیب‌ها توصیه من‌اند، نه نتیجه آزمون مستقل. هیچ‌کدام UX خوب را تضمین نمی‌کنند. معیار نهایی: فروشنده کم‌تجربه بتواند بدون راهنمایی محاسبه، صدور، چاپ و ثبت پرداخت را درست انجام دهد.

### اولویت جدید: سرعت روی اینترنت ضعیف ایران

انتخاب نهایی باید با `docs/PERFORMANCE_BUDGET.md` سازگار باشد. هیچ رتبه‌بندی سرعت یا عدد bundle واقعی برای گزینه‌ها در این تحقیق اندازه‌گیری نشده است.

- PrimeVue همچنان پیشنهاد مشروط برای اجزای موردنیاز فروشگاه است؛ با import انتخابی و بارگذاری بخش‌ها هنگام نیاز. حالت Unstyled ظاهر آماده را حذف می‌کند، اما خودبه‌خود JavaScript همه اجزا را کوچک یا حذف نمی‌کند.
- Reka گزینه مناسبی برای رابط کم‌جزء و اختصاصی است؛ صرف بدون‌استایل‌بودن ثابت نمی‌کند خروجی نهایی آن از گزینه دیگر سبک‌تر است.
- Nuxt UI نیز باید با همان فرم ورود و فاکتور چندردیفی و همان فونت/قابلیت‌ها سنجیده شود؛ سرعت توسعه با سرعت دانلود یکی نیست.
- Skillهای Claude فقط ابزار مرحله طراحی‌اند و نباید وابستگی زمان اجرای مرورگر شوند. جلوه‌های نمایشی سنگین در پنل فروشنده اولویت ندارند.
- بعد از انتخاب اولیه مالک، حجم فشرده همه فایل‌های لازم برای ورود/محاسبه، تعداد درخواست‌ها و زمان قابل استفاده‌شدن روی شبکه کند اندازه‌گیری شود؛ در صورت رد بودجه، تصمیم انتخاب با شواهد بازبینی شود. همه کتابخانه‌ها را صرفاً برای مقایسه در برنامه نصب نکن.

## ۵. هنگام دیدن نمونه‌ها به چه چیزی توجه کنید؟

1. فرم‌ها، انتخاب‌ها، فهرست‌ها و خطاها را ببینید؛ فقط homepage تبلیغاتی را ملاک نگذارید.
2. آیا عدد بزرگ، نوشته فارسی، فرم طولانی و موبایل خوانا می‌ماند؟
3. آیا اجزا می‌توانند ظاهر مستقل بگیرند یا صرفاً قالب آماده را پسندیده‌اید؟
4. تنوع بصری Skill را از امکانات library جدا ارزیابی کنید.
5. انتخاب خود را با نام مسیر A/B/C یا نام Skill + library اعلام کنید. جهت ظاهری می‌تواند بعداً با سه طرح محاسبه/فاکتور مقایسه شود.

پرامپ اجرای مرحله‌ای اکنون در `docs/prompts/UI_UX_RAPID_IMPLEMENTATION_PROMPT.md` آماده است: ابتدا وایرفریم/اتود، رنگ، لوگو، فونت و toolkit برای تأیید؛ سپس نسخه/راه‌اندازی ابزار منتخب، توکن‌ها، نقشه صفحات و جزئیات اجرا. این فایل انتخاب نهایی را به جای شما انجام نمی‌دهد. تایم‌باکس اجرا هدف کار فعال است، نه تضمین زمان یا مجوز حذف معیار سرعت و صحت.
